# SharedTypes Module

## Overview

The SharedTypes module is a **C language bridge module** that provides type definitions shared between Swift code and Metal GPU shaders. It serves as the foundation for Swift/Metal interoperability in the CoreSpice photonic simulation framework.

This module is configured as a Swift Package Manager target with:
- **Path**: `Sources/SharedTypes`
- **Public Headers Path**: `include`
- **Dependencies**: None (standalone C module)

## Type Definitions

### SpiceComplex

```c
typedef struct __attribute__((packed)) {
    double real;
    double imag;
} SpiceComplex;
```

**Purpose**: Double-precision complex number for the SPICE simulation engine.

| Field | Type | Description |
|-------|------|-------------|
| `real` | `double` | Real part of the complex number |
| `imag` | `double` | Imaginary part of the complex number |

**Memory Layout**: 16 bytes (packed)

**Usage Context**: Intended for SPICE circuit simulation kernels requiring high precision. Currently defined but **not actively used** in the codebase - the photonic simulation uses `float2` (single-precision) for GPU efficiency.

---

### MZICoefficients

```c
typedef struct __attribute__((packed)) {
    float m00_real;
    float m00_imag;
    float m01_real;
    float m01_imag;
    float m10_real;
    float m10_imag;
    float m11_real;
    float m11_imag;
} MZICoefficients;
```

**Purpose**: 2x2 transfer-matrix coefficients for a Mach-Zehnder Interferometer (MZI).

The matrix is structured as:
```
| m00  m01 |
| m10  m11 |
```

Each element is a complex value stored as a `(real, imag)` pair.

| Field | Type | Description |
|-------|------|-------------|
| `m00_real`, `m00_imag` | `float` | Top-left matrix element |
| `m01_real`, `m01_imag` | `float` | Top-right matrix element |
| `m10_real`, `m10_imag` | `float` | Bottom-left matrix element |
| `m11_real`, `m11_imag` | `float` | Bottom-right matrix element |

**Memory Layout**: 32 bytes (packed)

**Usage**:
- Generated by `CoefficientGenerator.swift` from MZI block parameters
- Passed to Metal kernels (`applyLayer512_even`, `applyLayer512_odd`)
- Stored in `LayerPlan512` for GPU dispatch

---

### LayerDescriptor

```c
typedef struct __attribute__((packed)) {
    uint32_t offset;
    uint32_t count;
    uint32_t pattern;
} LayerDescriptor;
```

**Purpose**: Describes a single layer within a photonic mesh (Clements/Reck architecture).

| Field | Type | Description |
|-------|------|-------------|
| `offset` | `uint32_t` | Index of the first MZI unit in this layer (0 for even, 1 for odd) |
| `count` | `uint32_t` | Number of MZI units (pairs) in this layer |
| `pattern` | `uint32_t` | Layer pattern: `0` = even-column layer, `1` = odd-column layer |

**Memory Layout**: 12 bytes (packed)

**Usage**:
- Created by `PhotonicCompiler.swift` when compiling a mesh
- Passed to GPU kernels via `setBytes()` in `MetalBackend.swift`
- Controls which port pairs are processed by each kernel dispatch

## Swift/Metal Interoperability

### Conditional Compilation

The header uses preprocessor directives to support both Metal and C/Swift contexts:

```c
#ifdef __METAL_VERSION__
#include <metal_stdlib>
using namespace metal;
#else
#include <stdint.h>
#endif
```

This allows the same type definitions to be:
- Imported by Swift via `import SharedTypes`
- Included by Metal shaders via `#include "SharedTypes.h"`

### Memory Layout Considerations

All structs use `__attribute__((packed))` to ensure:
1. Consistent memory layout across Swift and Metal
2. No padding between struct members
3. Predictable buffer access patterns in GPU kernels

### Usage Pattern in Swift

```swift
import SharedTypes

// Creating coefficients
let coeffs = MZICoefficients(
    m00_real: 1.0, m00_imag: 0.0,
    m01_real: 0.0, m01_imag: 1.0,
    m10_real: 0.0, m10_imag: 1.0,
    m11_real: 1.0, m11_imag: 0.0
)

// Creating layer descriptor
let desc = LayerDescriptor(
    offset: 0,
    count: 256,
    pattern: 0  // even pattern
)
```

### Usage Pattern in Metal

```metal
#include "SharedTypes.h"

kernel void applyLayer512_even(
    device float2* state [[buffer(0)]],
    const device MZICoefficients* coeffs [[buffer(1)]],
    constant LayerDescriptor& desc [[buffer(2)]],
    uint2 tid [[thread_position_in_grid]]
) {
    if (tid.x >= desc.count) return;
    MZICoefficients m = coeffs[tid.x];
    // ... matrix operations
}
```

## Code Review Notes

### Quality Assessment: Good

The implementation is clean, well-documented, and follows best practices for Swift/Metal interoperability.

### Strengths

1. **Comprehensive Documentation**: Each type has inline comments explaining its purpose, structure, and usage.

2. **Proper Include Guards**: Uses standard `#ifndef`/`#define`/`#endif` pattern.

3. **Cross-Platform Compatibility**: Conditional compilation correctly handles both Metal and C/Swift contexts.

4. **Packed Structs**: Using `__attribute__((packed))` ensures binary compatibility between Swift and Metal.

5. **Appropriate Precision Choices**:
   - `MZICoefficients` uses `float` for GPU efficiency (32 bytes is cache-friendly)
   - `SpiceComplex` uses `double` for simulation accuracy

### Observations

1. **SpiceComplex is Unused**: The `SpiceComplex` type is defined but not currently used anywhere in the codebase. The photonic simulation uses `float2` directly. This type appears to be reserved for future SPICE simulation kernels that may require double precision.

2. **Duplicate Shader Files**: Both `CoreSpiceBackend` and `PluginsPhotonic` contain identical `PhotonicKernels.metal` files. This is likely intentional for module bundling but could lead to maintenance overhead.

3. **Pattern Field Redundancy**: In `LayerDescriptor`, the `pattern` field (0 or 1) and `offset` field both encode whether it's an even/odd layer. The kernel already selects even/odd by function name (`applyLayer512_even` vs `applyLayer512_odd`), making `pattern` somewhat redundant within a single kernel. However, this design provides flexibility for unified kernels in the future.

### Potential Improvements

1. **Consider Adding Validation Macros**: Static assertions could verify expected struct sizes:
   ```c
   #ifndef __METAL_VERSION__
   _Static_assert(sizeof(MZICoefficients) == 32, "MZICoefficients size mismatch");
   _Static_assert(sizeof(LayerDescriptor) == 12, "LayerDescriptor size mismatch");
   #endif
   ```

2. **Consider Complex Number Helpers**: Adding inline functions for complex multiplication could improve code reuse:
   ```c
   #ifdef __METAL_VERSION__
   inline float2 cmul(float2 a, float2 b) {
       return float2(a.x * b.x - a.y * b.y, a.x * b.y + a.y * b.x);
   }
   #endif
   ```

3. **Remove or Document SpiceComplex**: Either remove the unused type or add a note explaining the planned use case.

### No Critical Issues Found

The module is production-ready and correctly implements the Swift/Metal bridging pattern.
